# РНБ WarDogs — Discord bot

Автоматизация Discord-сервера клана «РНБ» (WarDogs): провижининг структуры,
самостоятельный онбординг, операции и отчёты по матчам — всё через кнопки/
Modal, без слэш-команд для рядовых участников (кроме `/post-onboarding` —
разовая публикация контента для Officer+).

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Заполни `.env`:

* `DISCORD_BOT_TOKEN` — токен бота из Discord Developer Portal.
* `DISCORD_GUILD_ID` — (опционально, для разработки) ID тестового сервера,
  чтобы slash-команды синхронизировались мгновенно, а не до часа.

### Чек-лист перед первым запуском (Фаза 0)

* [ ] Создано приложение и бот в Discord Developer Portal
* [ ] Бот приглашён на сервер с правами: Manage Channels, Manage Roles,
      Send Messages, Embed Links, Attach Files, Use Application Commands
* [ ] Роль бота в списке ролей сервера — ВЫШЕ всех ролей, которые он
      создаёт/раздаёт (иначе `create_role`/`create_channel` с overwrites
      будут падать с `Forbidden`)
* [ ] Токен лежит в `.env`, `.env` не закоммичен
* [ ] В Developer Portal → Bot включён привилегированный интент **Message
      Content Intent** (нужен для команды `!tr` — иначе бот не увидит текст
      сообщений)

## Запуск (локально)

```bash
python bot/main.py
```

После этого можно выключить `.venv`/бота на своём ПК — он больше не
нужен для работы бота.

## Команды

### `/setup-server`

Доступна только владельцу/администратору сервера. Читает
`bot/config/server_structure.yaml` и идемпотентно создаёт недостающие роли,
категории и каналы (с permission overwrites для каналов с `restricted_to`).
Повторный запуск ничего не дублирует — в конце присылает embed-отчёт: что
создано, что уже было, что не удалось (например, не хватило прав).

Имена каналов в конфиге не обязательно писать заранее в "дефисном" виде —
`_shared.normalize_channel_name()` (нижний регистр, пробелы → дефисы)
применяется и при создании, и при проверке "уже существует", и в
`/sync-server`, так что предсказанное имя всегда совпадает с тем, что реально
присвоит Discord (категорий это не касается — их Discord не нормализует).

Конфиг можно редактировать и дополнять — при следующем запуске команда
добьёт недостающее. **Никогда ничего не удаляет** — для удаления того, что
пропало из конфига, см. `/sync-server` ниже.

**Права категорий — исключение из «никогда не трогает существующее»**: если
у категории в `categories[].restricted_to` (тот же формат, что у каналов)
задан список ролей — `/setup-server` синхронизирует overwrites категории при
КАЖДОМ запуске, даже если категория уже существовала. Иначе правка
`restricted_to` в конфиге никогда бы не долетала до уже созданных на сервере
категорий — команда бы просто молча продолжала игнорировать расхождение.
Каналы так не работают (у них создание по-прежнему одноразовое, права не
пересинхронизируются) — сознательная асимметрия, не баг.

Про гейтинг категорий (кто что видит) — см. раздел «Гейтинг категорий» ниже.

### `/sync-server`

Доступ — **уже, чем у `/report`/`/start-op`**: только Офицер или Верховный
Главнокомандующий (`sync.allowed_roles` в конфиге), не Глава отряда. Причина
— это единственная команда бота, которая **удаляет** данные с сервера.

Защита в два независимых слоя, не один самодельный `if`:
1. **Discord-нативный барьер**: команда объявлена с
   `@app_commands.default_permissions(manage_guild=True)` — по умолчанию
   Discord вообще не даёт открыть/вызвать эту команду тем, у кого на сервере
   нет права **Manage Server** (Управление сервером). Это проверяется на
   стороне Discord, до того как наш код вообще получит interaction.
2. **Проверка роли в коде** (`_shared.has_access` + `sync.allowed_roles`) —
   второй, независимый слой поверх первого.

> **Ручной шаг, не часть `/setup-server`**: `default_permissions` — это
> только *подсказка* Discord'а по умолчанию, а не автоматическая выдача прав
> ролям. Чтобы Офицер и ВГК реально могли вызвать `/sync-server`, зайди в
> Настройки сервера → Роли → (роль) → включи **Manage Server**, для обеих
> ролей. Это открывает всей роли широкое право на уровне всего Discord-сервера
> (не только для этой команды) — соизмеримо с тем, что `/sync-server`
> необратимо удаляет данные. Глава отряда (`Squad Lead`) сюда намеренно **не**
> включён — это уже, чем доступ к `/report`/`/start-op`, при желании дать
> Squad Lead доступ надо синхронно поменять и `sync.allowed_roles` в конфиге,
> и список ролей с Manage Server в Discord — иначе два слоя защиты разъедутся.

Сканирует **весь сервер целиком** — `guild.roles` и `guild.channels`
полностью, а не только то, что перечислено в `server_structure.yaml`:
* роль — кандидат на удаление, если её нет в `roles` конфига (исключения:
  `@everyone` и managed-роли — интеграции, роль самого бота);
* категория — кандидат, если её нет в `categories` конфига (удаляется вместе
  со всеми каналами внутри);
* канал внутри известной категории — кандидат, если его нет в списке
  `channels` этой категории в конфиге;
* **канал вообще без категории** (например случайно оставшийся Discord'ом
  по умолчанию `general`) — тоже кандидат, эта ветка не привязана к yaml
  вообще.

Категории с `dynamic: true` (`🎯 АКТИВНЫЕ ОПЕРАЦИИ`) — исключение: их
содержимое никогда не сканируется, им управляет `/start-op`.

Ничего не удаляется молча: перед удалением бот присылает список всех
кандидатов и ждёт подтверждения кнопкой (60 сек, потом отмена по таймауту).
После подтверждения — необратимо удаляет и присылает итог (удалено/не
удалось).

### 📋 Отчёт по матчу (кнопка, не команда)

`/report` больше не существует — кнопка **«📋 Отчёт по матчу»** висит на
explainer-сообщении в `карта-и-счёт`. Доступ — тот же список ролей, что
раньше проверял `/report` (`restricted_to` канала `report.channel` в
конфиге): Глава отряда/Офицер/ВГК/админ, остальным — вежливый ephemeral-
отказ прямо на клик.

Клик → **Modal** с 5 текстовыми полями (лимит Discord на Modal, ровно
столько и нужно): карта, наш счёт, счёт Valkyra, счёт Manticore, заметки.
Сабмит → ephemeral-панель с кнопками **статуса** (в процессе/победа/
поражение) и **«зажаты кем»** (нет/Valkyra/Manticore/обе) — WarDogs это три
фракции, а не «мы против всех», старая схема с одним «score_other» такого
не отражала. Обе кнопочные группы просто держат выбор в атрибутах Python-
объекта `StatusPincerView` (не в custom_id, не в отдельном сторе — вью живёт
секунды, персистентность не нужна), финальная кнопка **«✅ Отправить»**
постит embed в `карта-и-счёт` и пишет строку в CSV.

`bot/data/match_log.csv` — новая схема: `score_us`, `score_valkyra`,
`score_manticore`, `pincered_by` (вместо `score_blue`/`score_other`/
`pincered`). Полей `squads_present` и `screenshot` больше нет — Modal не
принимает файлы вообще, а 5 полей уже все заняты числами/картой/заметками.

`report.py::_append_log` сверяет заголовок файла с `CSV_FIELDS` перед
каждой записью и **бросает исключение**, если не совпадает — при смене
схемы данных старый файл с чужим заголовком иначе молча портит все
последующие строки (ровно это один раз и произошло при разработке).

### `!tr <текст>`

Текстовая команда (не slash), доступна всем. Автоматически определяет
направление перевода: если в тексте есть кириллица — RU→EN, иначе EN→RU.
Отвечает переводом в том же канале (reply, без лишнего пинга). Перевод — через
`deep-translator` (Google Translate без официального ключа/квоты API).

#### Зеркалирование RU↔EN-каналов (опционально, выключено по умолчанию)

В `server_structure.yaml` есть секция:

```yaml
translate:
  mirror_pairs_enabled: false
  mirror_pairs:
    - {ru_channel: "объявления-announcements", en_channel: "..."}
```

Если включить `mirror_pairs_enabled: true` и заполнить пары каналов —
каждое обычное сообщение в `ru_channel` будет переведено и продублировано в
`en_channel` через webhook, подписанным именем и аватаркой автора. Свои же
переведённые сообщения бот не зеркалит повторно (проверка по `webhook_id`).
Webhook (`РНБ Translate Mirror`) создаётся автоматически при первом
срабатывании в целевом канале — боту нужны права Manage Webhooks.

### 🚀 Начать операцию (кнопка, не команда)

`/start-op` и `/end-op` тоже убраны как команды. Доступ к запуску операции —
тот же уровень, что раньше проверял `/start-op` (Глава отряда/Офицер/ВГК/
админ).

В игре у отряда уже есть свой приватный голосовой канал прямо в матче (Esc →
Create/Join Squad) — Discord не дублирует его во время боя. Кнопка закрывает
то, что игра не даёт: координацию **до** и **после** операции.

Кнопка **«🚀 Начать операцию»** висит на explainer-сообщении в
`сбор-на-операцию`. Клик → права проверяются сразу (не молча) → ephemeral
**Select** для отряда (5 отрядов + «без привязки») → выбор открывает
**Modal**: `Server ID` (ровно 6 цифр, валидируется) и карта (необязательно).
Modal не поддерживает выпадающие списки, поэтому отряд выбирается ДО Modal,
а не внутри него — два шага вместо одного, но оба без единого напечатанного
слова команды.

Сабмит:
* создаёт временную пару каналов (текст + голос) в категории
  `ops.temp_category` (`🎯 АКТИВНЫЕ ОПЕРАЦИИ`) с одинаковым именем
  `операция-{отряд}-{id}` — это и есть механизм связи пары без глобального
  состояния, переживает рестарт бота;
* постит анонс-embed в `ops.announce_channel` (`сбор-на-операцию`) — поле
  **Server ID** подписано явно («зайти: Обозреватель серверов → Join By
  ID»), отряд (с упоминанием его роли, если выбран), карта, ссылки на
  каналы, и кнопка **✅ Иду** (см. ниже);
* каналы открыты всем — цель собрать людей на операцию, не спрятать их.

Логика создания вынесена в `Ops.create_operation()` — общий код и для
кнопки, и для чего угодно ещё, что в будущем тоже захочет создавать
операции.

Кнопка **✅ Иду** под анонсом — persistent (`custom_id`, `timeout=None`,
переживает рестарт бота: регистрируется заново в `Ops.__init__` при каждом
старте) и работает как **toggle**: клик добавляет упоминание нажавшего в поле
«Участники» прямо в embed анонса, повторный клик тем же человеком — убирает
его оттуда (поле возвращается к «—», если список опустел). Без отдельного
in-memory состояния — список участников читается и переписывается из
текущего embed'а самого сообщения, так что рестарт бота ничего не теряет.

Автоочистка: раз в `ops.cleanup_delay_seconds` (по умолчанию 300 — 5 минут)
бот проверяет, пуст ли голосовой канал операции; как только да — удаляет оба
канала пары. Если бот перезапускался во время активной операции — на старте
(`on_ready`) он сам находит незавершённые пары каналов в
`ops.temp_category` и возобновляет слежку **с полной задержки заново** (не
"оставшееся время") — это упрощение, не точный resume; проверено на реальном
сервере (см. историю коммитов), что таймер при этом не задваивается и не
удаляет раньше срока.

**🛑 Завершить операцию** заменяет `/end-op` — кнопка постится один раз
прямо в канале операции при её создании (`EndOpView`). Не персистентная
(не переживает рестарт бота — если он перезапустится посреди операции,
кнопка на этом конкретном канале перестаёт отвечать), но это не тупик:
канал всё равно сам почистится штатным watcher'ом/reconciliation, просто
без досрочного клика придётся ждать автоочистку.

> Старые статичные отрядные текстовые каналы (штурм/логистика/...) и
> голосовой-триггер «➕ Создать голосовой» убраны из
> `server_structure.yaml` ещё раньше — они не несли функции. Роли отрядов
> остались — как метка специализации, для пинга в анонсе операции и для
> проверки в кнопке «Начать операцию».

### `/post-onboarding` (команда — Officer+ единоразовая публикация)

Единственная member-facing команда, которая осталась слэш-командой — она не
для рядовых участников, а для Офицера/ВГК, чтобы (пере)опубликовать
закреплённый контент. Доступ — Officer+ (`sync.allowed_roles`). Постит/
обновляет **три** закреплённых сообщения:

1. В `#правила-verification` — «📜 Контракт РНБ»: клик по кнопке отряда
   подаётся как подпись контракта (слушаешь Главу отряда на операции, не
   сливаешь стратегию, уважаешь остальных) со ссылкой на полные правила.
   6 кнопок: 5 отрядов (Штурм/Логистика/Разведка/Транспорт/Поддержка) +
   отдельная **«🎮 Готов играть сейчас»** (самостоятельный toggle, не
   связан с отрядом — просто mentionable-роль, чтобы звать людей на
   внеплановую игру пингом в `сбор-на-операцию`, не через кнопку «Начать
   операцию»). Persistent view, переживает рестарт бота.
2. В `#сбор-на-операцию` — explainer для пустого состояния + кнопка
   **«🚀 Начать операцию»**.
3. В `#правила-verification` — путеводитель по рангам (Новобранец → Боец →
   Глава отряда → Офицер → ВГК) и «Полезные ссылки» (постоянный инвайт-
   линк, создан ботом; ссылка на Steam-группу — не запощена, нет URL).

Все публикации — через `_shared.replace_pinned_by()`: перед постом ищет
своё предыдущее закреплённое сообщение в канале (по заголовку embed'а) и
заменяет его, а не плодит дубликаты при повторном запуске.

По клику на кнопку отряда: снимает предыдущую отрядную роль, если была,
выдаёт новую + роль «Новобранец | Recruit», если её ещё не было. Ответ —
ephemeral-сообщение с текстом **и настоящей кнопкой-ссылкой**
(`discord.ButtonStyle.link`, `url=` реальный `jump_url` канала) на
`#сбор-на-операцию` — не текстовое упоминание, кликабельный переход. Ошибка
прав (роль бота не выше ролей отрядов) — понятное ephemeral-сообщение, не
тихий сбой.

Замена Carl-bot/reaction-roles для выбора отряда — ничего внешнего
подключать не нужно.

### 📊 Статистика (кнопка, не команда)

`/stats` заменена кнопкой **«📊 Статистика»** на закреплённом стартовом
посте форума `тактика-обсуждение`. Доступ — тот же уровень, что у отчёта по
матчу (данные оттуда же). Только читает `bot/data/match_log.csv` — новых
данных не собирает. Показывает: всего операций, счёт побед/поражений/в
процессе, сколько раз отмечен «зажим» и кем (`pincered_by`) и в каком
проценте матчей, разбивку побед/поражений по каждой карте. Если лога ещё
нет — вежливое ephemeral-сообщение вместо ошибки.

### Форум-каналы: `тактика-обсуждение` и `хайлайты-highlights`

Оба — тип `forum` (`GUILD_FORUM`), не текстовый канал; постинг туда =
создание треда, а не отправка сообщения. Discord не позволяет сменить тип
уже существующего канала — конвертация была сделана удалением старого
text-канала и созданием нового форума с тем же именем через
`/setup-server` (сначала вручную проверено, что в старых каналах не было
реального пользовательского контента, только сообщения бота).

Пин в форуме работает иначе, чем в обычном канале — закрепляется **тред
целиком** (`Thread.edit(pinned=True)`), а не сообщение
(`Message.pin()`) — `_shared.replace_pinned_thread()` отдельно от
`_shared.replace_pinned_by()`, не переиспользует её код напрямую.

* `тактика-обсуждение` — стартовый (закреплённый) тред: тактическое
  руководство клана + кнопка «📊 Статистика» (см. выше).
* `хайлайты-highlights` — стартовый тред с объяснением: «постишь клип — это
  твой тред, голосуем реакциями».

### Гейтинг категорий

Все категории, кроме `📜 ПРИВЕТСТВИЕ`, закрыты от `@everyone` и открыты
только по `restricted_to` — новый участник видит только
`правила-verification`, пока не выберет отряд (подписав контракт) через
`/post-onboarding` (получение отрядной/ранговой роли открывает всё
остальное, кроме `🔒 ШТАБ ОФИЦЕРОВ`, куда нужна отдельная офицерская роль).

### «РНБ: Повысить» (user context-menu — правый клик по участнику)

Не слэш-команда — пункт контекстного меню при клике правой кнопкой по
участнику в списке (или в его профиле). Доступ — тот же Officer+
(`sync.allowed_roles`).

Показывает Select только с рангами **выше** текущего ранга участника
(`bot/cogs/promotion.py::RANK_HIERARCHY` — Новобранец → Боец → Глава
отряда → Офицер → ВГК), можно прыгнуть сразу через несколько ступеней.
Выбор снимает текущую ранговую роль (если была) и выдаёт новую, пробует
отправить повышенному ЛС (закрытые ЛС — не ошибка, просто без
уведомления).

**Это и есть ответ на «как люди получают Офицера/ВГК без меня»**: как
только на сервере есть хотя бы один Офицер, ОН может повышать дальше
через это меню — но самого первого Офицера всё равно должен назначить
владелец сервера вручную через настройки ролей Discord, обойти этот шаг
нечем.

## Структура

```
bot/
  main.py              # точка входа, загрузка cogs, синхронизация команд
  cogs/
    _shared.py           # конфиг, доступ по ролям, список отрядов, pinned-хелперы
    provisioning.py     # /setup-server, /sync-server (единственные оставшиеся команды помимо post-onboarding)
    report.py            # кнопка «📋 Отчёт по матчу» + Modal + статус/зажаты
    translate.py         # !tr + опциональное зеркалирование каналов
    ops.py                # кнопка «🚀 Начать операцию» + Select + Modal, кнопка завершения
    onboarding.py         # /post-onboarding: контракт-приветствие, explainer операций, ранги/ссылки
    stats.py              # кнопка «📊 Статистика» в форуме тактика-обсуждение
    promotion.py           # «РНБ: Повысить» — user context-menu
  config/
    server_structure.yaml
  data/                 # создаётся кодом; не коммитится (см. .gitignore)
```
